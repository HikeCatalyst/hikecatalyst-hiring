# Getting Started

Read this first. It takes 10 minutes.

## 1. Find your role

Open the [role list](README.md) or the site home page and pick the role you applied for. Developers also have two tracks:

- **MERN Developer:** classic full stack tasks, no AI feature to build. Good starting point for freshers.
- **AI Applied Full Stack Developer:** apps that use an LLM, with guardrails and testing.

Each role folder lists its tasks with a level (Easy, Medium, Advanced). We tell you which tasks to do. If you choose, start with the easiest one.

## 2. Set up your accounts and tools (everyone)

1. A free **GitHub** account.
2. **Git** installed: `git --version`.
3. Tell Git who you are:

   ```bash
   git config --global user.name "Your Name"
   git config --global user.email "you@example.com"
   ```
4. Log in from the terminal: `gh auth login` (GitHub CLI), or set up an SSH key as described in [SUBMISSION.md](SUBMISSION.md).
5. Role extras: developers need Node.js 20+ and VS Code (see the [MERN guide](assignments/mern_developer/getting_started.md)). Other roles need Google Sheets or Excel and a Markdown editor.

## 3. Plan your 5 days

| Day | Do |
|-----|----|
| 1 | Read the task twice. Write down the requirements and questions. Set up the repo. |
| 2-3 | Build the core. Commit often. |
| 4 | Finish edge cases, tests and the README. |
| 5 | Review it like a stranger would, then submit. |

## 4. Work in your own repo

Each task ends with a "Repo and submission" section: a repo name and the commands to create a public repo on your own GitHub. Do not push to this repository.

## 5. Use AI honestly

AI tools are allowed. Keep an `AI_LOG.md` with what you asked and what you fixed. In the follow-up call we ask you to explain and change your own code.

## 6. Submit

Follow [SUBMISSION.md](SUBMISSION.md): add one file with your repo links through a pull request.

## 7. If you are stuck

Write down what you tried. Partial work with honest notes is welcome.
